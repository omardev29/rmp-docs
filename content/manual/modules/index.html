Modules

The core is what every game is made of. The modules are what a game takes when it needs them: each one is a header of its own under include/rmp/, there is no header that includes them all, and a game includes only the ones it uses. Which header holds what is in headers.

  • Input — named actions with any number of bindings, movement in eight directions in one call, the mouse and a finger as one pointer, and who gets to hear a press.
  • Interface — menus, HUDs and settings screens in immediate mode, playable with a mouse, a finger, a keyboard or a gamepad.
    • Interface layout — rows, columns, panels, stacks, grids, scrolling, and how big each thing is.
    • Interface controls — checkboxes, sliders, dropdowns and text fields that write into your variables.
    • Interface style — themes, variants, sizes, transitions, breakpoints and fonts.
  • Assets — files in resources/, loaded by name, the same from loose files or from a pack.
  • Sprites — what an object looks like: a texture, or an Aseprite file whose tags are its animations.
  • Tilemaps — levels designed in LDtk or Tiled, drawn, collided with, and turned into objects.
  • Audio — sound effects and music by name, on volume buses a settings screen can move.
  • Saving — rmp::Value and rmp::save: a tree of data written to the right folder on every platform.
  • Random — random numbers you can reproduce.
  • Ads — interstitial and rewarded ads on Android, and the same calls doing nothing everywhere else.
