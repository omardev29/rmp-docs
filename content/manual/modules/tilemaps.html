Tilemaps

A level is designed in an editor and loaded by name. Every scene has a map: the scene draws it under everything, stops solid objects at its solid cells, and the enemies, coins and doors you placed in the editor turn up in the game as objects. The editor stops being a file format and becomes the place where the level is made.

Loading a level

The map is a field of the scene. Assign it in _ready():

map = rmp::assets::load_map("world.ldtk");

That is all it takes for the level to be on screen and solid. There is no draw() to call: the scene draws the map first, inside the camera, so the objects stand on it and the HUD your _draw() paints stays on top. A scene that never assigns its map — a menu — has an empty one, which costs nothing.

load_map() picks the reader by the file's extension:

FileEditorStatus
.ldtkLDtkThe one the framework tests and keeps up to date.
.jsonTiledRead as it is, with the tests it has. It gets nothing new.

LDtk is the primary one because it is the more modern editor — auto-layers, IntGrid, entities with typed fields, worlds of many levels, and a JSON format it documents and has kept stable since 1.5 — and holding two readers to the same level of testing is more than it is worth. Whichever made it, a map is the same rmp::Tilemap afterwards: nothing past the parser knows which editor drew it.

A map is not shared the way a texture is. It belongs to one scene, moves rather than copies, and is read from the file each time it is loaded; the tileset images it draws with are ordinary textures and are shared.

What the scene does with it

Draws it
Underneath every object, layer by layer from the bottom, inside the scene's camera.
Stops solid objects at its solid cells
An object that is solid and not immovable cannot move into a solid cell: the floor holds the player up, a wall stops it, a ceiling ends a jump, and the Platformer behavior counts the floor as ground. A coin, a trigger, a bullet or a platform the game moves by hand is not stopped.
Becomes the edge of the world
An object whose edges say what to do at the edge of the world — clamp, bounce, wrap — and whose bounds are left empty takes the map's bounds as that edge rather than the view's, so a player clamped to the world is clamped to the level.

Movement against the map is worked out one axis at a time — across, then down — so a player running along a floor made of separate tiles does not catch on the seams between them. A fast object moves in steps of at most half a cell, so a fall faster than a tile per frame still lands on the floor instead of passing through it. The camera is the one thing to set yourself, and it is one line: camera.limits = map.bounds(); keeps the view inside the level.

Levels from LDtk

An LDtk project can hold many levels. Without a name, load_map() loads the first; with one, it loads the level of that identifier:

map = rmp::assets::load_map("world.ldtk", "Desert");

Starting from "" — the first level, whatever it is called — means renaming or reordering levels in LDtk does not stop the game starting at the beginning. A name the project does not have loads nothing and the log lists the names it does have.

Setting up the project

  • Images next to it. The tileset images go in resources/ beside the .ldtk. LDtk stores paths relative to the project, and only their file name is kept, because resources/ is flat. A tileset image that is not there, or does not decode, is a warning naming the file and a failed load; the level still loads, and that tileset draws nothing. A tileset must be a picture load_texture() reads, such as a PNG; LDtk's built-in icon atlas has no file and draws nothing either.
  • Solid cells. An IntGrid layer value whose identifier is solid makes every cell painted with it solid. So does any tile tagged solid through its tileset's enum for tile marking, even under another tile. Either is compared without case, because LDtk's default identifier style saves solid as Solid.
  • Layers. Tiles, AutoLayer, and IntGrid layers with an auto-layer ruleset are drawn, bottom to top, each with its own grid size, offset and opacity, every tile flipped and faded as LDtk placed it. A layer hidden in LDtk is not drawn and is still solid, which is the shape of a collision layer nobody needs to see.
  • Levels in separate files. With "Save levels to separate files" on, each level is a .ldtkl beside the project; copy them into resources/ too. Loading a .ldtkl on its own is refused, because its tilesets and layer definitions live in the .ldtk.
  • The format. The reader follows the JSON format of LDtk 1.5 and later. A project saved by an older LDtk is read anyway and says once that saving it again in a current LDtk is the fix.

Not read: level backgrounds, parallax, IntGrid values other than solid, and the fields of a level itself.

The world

In LDtk's GridVania and Free layouts every level has a place in one world, and the map keeps it: bounds() is where the level sits in the world, and every position the map hands out — objects, points, solid cells — is in those same world units. A level loaded at x = 720 starts at 720, not at 0. The linear layouts have no world, and each of their levels starts at 0,0.

That is what makes walking from one level into the next a single if. neighbour_at(point) names the other level of the world at a point, or "" while the point is still in this level or in no level at all. Change to that level and put the player at the same position, which still means the same place, because the coordinates are the world's:

class Level : public rmp::Scene {
public:
    Level(std::string name, Vector2 arrival) : _name(std::move(name)), _arrival(arrival) {}

private:
    void _ready() override {
        map = rmp::assets::load_map("world.ldtk", _name);
        _player = spawn<Player>({ .position = _arrival }).handle();
        camera.follow = _player;
        camera.limits = map.bounds();
    }

    void _update(float delta) override {
        const rmp::Object *player = _player.get();
        if (player == nullptr) return;
        const char *next = map.neighbour_at(player->position);
        if (next[0] != '\0') rmp::Scene::change<Level>(next, player->position);
    }

    std::string _name;
    Vector2 _arrival;
    rmp::Handle<rmp::Object> _player;
};

level() is the identifier of the level loaded. The platformer in examples/games/07_platformer is a world of three levels side by side in a GridVania layout, walked through exactly like this: level.cpp.

Objects from the editor

An LDtk entity, or an object on a Tiled object layer, is a rmp::MapObject: a type, a position, a size and a set of properties. A factory says what to make of each type, and spawn_objects() runs them all:

class LevelScene : public rmp::Scene {
    void _ready() override {
        map = rmp::assets::load_map("world.ldtk");
        map.on_object("Goblin", [](rmp::Scene &scene, const rmp::MapObject &o) {
            auto &goblin = scene.spawn<Goblin>({ .position = o.position });
            goblin.hp = o.property_int("hp", 20);
        });
        map.spawn_objects(*this);
        camera.limits = map.bounds();
    }
};

Three things in it matter:

  • on_object() is called after load_map(). Factories belong to the map that is loaded when they are registered: on an empty map they register nothing, and the next load_map() starts with none.
  • A second factory for the same type replaces the first. Two factories for one type is never what anybody means, and running both would spawn the object twice.
  • The position is the centre, as it is for every rmp::Object. The editors give a corner or a pivot; the conversion is done once, when the map is read, so no factory has to.

Properties

LDtk's entity fields and Tiled's custom properties are read by name. Every accessor takes a fallback, which is what comes back when the object has no property by that name, when the field was left empty in the editor, or when it holds another kind of value:

In LDtkIn TiledRead with
Intintproperty_int(key, fallback); a float is cut towards zero
Floatfloatproperty_float(key, fallback); an int is read too
Boolboolproperty_bool(key, fallback)
String, Multilinesstring, fileproperty_string(key, fallback)
Enumproperty_string: the value's name
Colorproperty_string: "#rrggbb"
EntityRefproperty_string: the iid of the entity it points at
Pointproperty_point(key): the world position of the centre of that cell
Array<Point>property_point(key, i) for each i below property_count(key)

A point comes back in the same world units as position, so a patrol route drawn in LDtk is used as it comes:

map.on_object("Bat", [](rmp::Scene &s, const rmp::MapObject &o) {
    auto &bat = s.spawn<Bat>({ .position = o.position });
    bat.speed = o.property_float("speed", 50);
    for (int i = 0; i < o.property_count("patrol"); i++) {
        bat.route.push_back(o.property_point("patrol", i));
    }
    if (bat.route.empty()) bat.route.push_back(o.position);
});

Not read: arrays of anything but points, and the FilePath and Tile field types.

Linking objects to each other

Every LDtk entity has an iid, a unique identifier, and an EntityRef field holds the iid of the entity it points at. Making the link is up to the game: keep the iid on the object, and compare.

map.on_object("Key", [](rmp::Scene &s, const rmp::MapObject &o) {
    auto &key = s.spawn<Key>({ .position = o.position });
    key.opens = o.property_string("opens"); // the iid of a Door
});
map.on_object("Door", [](rmp::Scene &s, const rmp::MapObject &o) {
    auto &door = s.spawn<Door>({ .position = o.position });
    door.iid = o.iid;
});

An iid also outlives the scene, which makes it the way to remember that a coin was collected or a door opened when the player walks back into a level: the platformer keeps the iids of what is gone in an rmp::global and skips them in its factories.

Objects with no factory

A type nobody registered still comes out, as a plain invisible rmp::Object with the position and the size, immovable. Whether it is solid depends on what it was:

  • A Tiled object with an area — a rectangle drawn on an object layer — is solid. That is the right default for a wall or a platform drawn as a shape.
  • A Tiled point, or anything with no width or no height, is a marker and is not solid: an invisible collider at a spawn point is not what anybody drew.
  • An LDtk entity is never solid on its own. Its box is only how big it looks in the editor; walls in LDtk are IntGrid.

Levels from Tiled

A Tiled map is the .json Tiled saves. What the reader expects of it:

  • CSV tile layers. A map whose layers are compressed or base64 is refused, and the log says where the setting is: Map, Map Properties, Tile Layer Format, CSV. CSV is Tiled's default for a new map.
  • Tilesets embedded, or saved as JSON. A tileset kept in a .tsx file is XML, which is not read: embed it in the map, or save the tileset as .tsj. Until then that tileset draws nothing, none of its tiles are solid, and the load counts as failed. The tileset image is looked up by its file name in resources/.
  • Solid tiles. Every tile of a layer whose class is solid is solid; so is a tile the tileset gives a bool property solid set to true.
  • Objects. The object's class is its type, its name is name, and rotation and gid are Tiled's. Rectangles, ellipses, points and polygons are placed by their top-left corner and tile objects by their bottom-left, and both arrive at their centre. Objects come out in the order the layer has them.

Tiled maps have no world: level() and neighbour_at() answer "", and the map starts at 0,0.

Asking the map

The scene uses the map for drawing and collision; the same questions are open to the game, in world units:

CallAnswers
solid_at(point)Whether a solid cell is under a point, on any layer.
solid_in(rect)Whether a solid cell covers any part of a rectangle. Every cell under it is checked, not only the corners. Touching is not covering: a box standing on the floor is not in the floor.
tile_at(layer, column, row)The tile in one cell of one layer, as its global tile id; 0 for an empty cell. Layers count from 0 at the bottom, and the cell is in that layer's own grid. For LDtk it is the topmost tile of the cell.
bounds()The level's rectangle in the world.
tile_size()One cell of the map's grid.
layer_count(), object_count()How many tile layers and how many objects it holds.

An enemy that turns round at the edge of its platform, rather than walking off it, asks whether there is floor just ahead of its feet:

// Walking right: is there anything to stand on one pixel ahead and one below?
const Rectangle body = world_collider();
const Vector2 ahead{ body.x + body.width + 1, body.y + body.height + 1 };
if (!scene()->map.solid_at(ahead)) velocity.x = -velocity.x;

draw() is public for a game that wants the map drawn somewhere else in its own order. The scene already draws it, so calling it as well draws it twice.

When a map cannot be read



A map that is missing or does not parse is an empty map:
valid() is false, every query answers zero,
empty or false, and on_object() registers nothing. The game runs, on a level with
nothing in it. Each reason is said in the log in words that name the file and the fix — the
compressed layers, the .tsx tileset, the level LDtk keeps in a file that is not in
resources/, the level name that is not in the project. A map file that is missing,
or does not parse, counts as a failed
load, and so does a tileset image that is not there or does not decode, so the boot check in CI
sees them.
