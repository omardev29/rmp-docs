Android

On Android the game is a native library inside an app. The app around it is raymob, a small implementation of raylib for Android — a Java activity and a C library of Android extras, vendored with the framework and patched where marked — and the Gradle build that makes it is driven by raylib_multiplatform.toml like every other build. The game's code does not change: raylib's Android glue starts it through the same main() a desktop uses.

Building it

rmp android
adb install -r <the APK rmp android printed>

rmp android regenerates the configuration and runs Gradle's debug build, and prints the APK it wrote. It needs the Android SDK and NDK; the versions CI builds with are pinned in thirdparty/FROZEN_VERSIONS.md — compile and target SDK 36, NDK r28, the CMake package of the SDK — and Gradle needs JDK 17 to run.

Gradle never runs CMake early enough to generate anything, so the build reads two files configure.py writes from the .toml: raymob/generated.properties, with the game's name, ids, version and switches, and raymob/app/generated/AndroidManifest.xml, the manifest with exactly the permissions and features the .toml asks for. Neither is committed, so neither can drift from the .toml. Building from Android Studio or with ./gradlew yourself, run python3 tools/configure.py first; Gradle says so when the first file is missing.

The game is compiled into one shared library named after [project] name, with its own copy of raylib built for Android — [raylib] disabled_modules applies to it as it does on a desktop. A release build is optimised and has RMP_PRODUCTION_BUILD at 1; a debug build has it at 0.

The application id

[android]
application_id = "com.yourname.yourgame"

This is the app's identity on the device and on Google Play, and on Google Play it is permanent: once an app is published under an id, the id can never change, and a new one is a new listing without its installs and reviews. rmp new fills it with a com.example. placeholder; a release is refused while it still says so, by rmp deploy before it tags and by CI when a tag arrives.

The id needs at least one dot, and every part starts with a letter. It also must not contain the string the build rewrites in raymob's sources on the way through, which is refused with the reason:

[android]
application_id = "com.raylib.raymob.mygame"

The version name and the version code come from the git tag, not from the .toml: v1.2.3 is version name 1.2.3 and version code 1002003. See Releases.

What the .toml decides

KeyBecomes
[window] titleThe app's name under its icon.
[window] orientationThe activity's screen orientation: "landscape", "portrait" or "unspecified". The same key sets iOS.
[android] min_sdkThe oldest Android the app installs on, as an API level from 21 to 36; 24, the default, is Android 7.0. The target SDK is fixed at 36, which Google Play requires.
[android] categoryandroid:appCategory, how the Play Store files the app: "game" by default. It is not what puts the icon in the launcher; that part is fixed.
[android] gl_versionThe OpenGL ES version a device must have to be offered the app. See below.
[android.display] keep_onThe screen never sleeps while the game runs.
[android.display] immersiveThe system bars are hidden.
[android.display] into_cutoutThe game draws behind the notch. rmp::ui keeps its own controls out of it, padding the interface by the safe area.
[android.permissions] internet, vibrationThe permissions the app asks for. Each one is shown on the Play listing, so ask for nothing you do not use. vibration is what raymob's Vibrate needs.
[android.features] gyroscope, accelerometertrue hides the app from devices without the sensor; false declares it optional.
[icon] source, adaptive_backgroundEvery launcher icon density, the round icon and the adaptive icon's foreground, made from one picture. That needs Pillow on the machine that configures.

All of the switches are true or false and nothing else; the string "false" is refused rather than read as yes. A permission is an element of the manifest, present or absent, which is why the manifest is generated rather than filled in.

[android]
min_sdk = 26

[android.display]
into_cutout = false

[android.permissions]
vibration = true

gl_version is a requirement, not a choice

[android] gl_version — "ES20", "ES30", "ES31" or "ES32", "ES30" by default — writes the manifest's <uses-feature android:glEsVersion>: devices without that version are not offered the app. It does not change how the game draws. raylib's Android build is compiled for OpenGL ES 2.0 whatever this says, so a higher value only narrows who can install the game. A game that needs no more than raylib draws with can ask for "ES20".

Assets and saves

Gradle copies resources/ into the APK's assets before it builds, and raylib's file functions read them there. The asset pack is left out: the pack is opened as a plain file, and inside an APK there is no such file, so Android always reads the loose copies — the files are in the APK unencrypted, and [resources] rres_password protects nothing on this target.

Saves go to the app's private internal storage, in a saves/ folder: no permission is needed, no other app can see them, and they are removed with the app.

Android-only extras: raymob

<raymob.h> adds what raylib does not have on a phone: vibration, the on-screen keyboard, the accelerometer and the gyroscope, the screen's orientation, keeping the screen on, the app's storage folder. It declares those functions on Android only, so calls to it are guarded:

#include <raylib.h>
#ifdef __ANDROID__
#include <raymob.h>
#endif

void on_hit() {
#ifdef __ANDROID__
    VibrateMS(40); // needs [android.permissions] vibration = true
#endif
}

examples/platform/02_mobile_raymob uses each of them; see its page.

Ads

[android.admob] enabled decides whether AdMob is in the build at all, and it is true in the .toml a new game starts with, set to Google's test ad units. false removes it completely: no Google Mobile Ads library, no advertising-ID permission, nothing to declare about advertising in Play's Data safety form, and the rmp::ads calls still compile and do nothing. It also switches itself off when Android is not a target, and it forces the internet permission on when it is on.

[android.admob]
enabled = false

The framework does not ship a consent form. Serving ads to players in the EEA or the UK requires one certified by Google, and adding it is yours before publishing with ads on.

Leaving the app

rmp::app::quit() ends the frame loop and, on Android, also tells the system the activity is finished, with ANativeActivity_finish. A process that simply stopped would leave its task in the recent-apps list, pointing at nothing.

Signing for Google Play

Google Play takes an Android App Bundle (an AAB) signed with your upload key. The key, and every password for it, are secrets, and none of them ever goes in raylib_multiplatform.toml — the .toml is committed, and there is no key in it for them. Create the upload keystore once and keep it somewhere you will not lose it:

keytool -genkey -v -keystore upload.jks -keyalg RSA -keysize 2048 -validity 10000 -alias upload

CI reads it from four repository secrets on GitHub:

SecretValue
ANDROID_KEYSTORE_BASE64The keystore file, base64-encoded: base64 -w0 upload.jks.
ANDROID_KEYSTORE_PASSWORDThe keystore's password.
ANDROID_KEY_ALIASThe key's alias: upload above.
ANDROID_KEY_PASSWORDThe key's password.

With them, the release bundle is signed with your key, its signature is verified, and it is attached to the release. Set the repository variable ANDROID_SIGNER_CN to the name your key was made with, and CI also checks the bundle is signed by that key and not merely by some key. Without the secrets, CI still builds and signs the bundle on every run — with a throwaway key made for that run — and names it …-NOT-FOR-PLAY.aab; that file is never attached to a release.

On your own machine the release bundle is Gradle's bundleRelease, run in raymob/ after python3 tools/configure.py:

python3 tools/configure.py
cd raymob
./gradlew bundleRelease

Gradle signs it when four environment variables say where the key is: ANDROID_KEYSTORE_FILE, the path to the keystore, and the same three passwords and alias as above. Without them the bundle comes out unsigned, which is fine for looking at and not accepted by Google Play.

When a Gradle build is killed

raymob's sources carry its own package name, and the build rewrites them to your application id on the way in and puts them back when it finishes. A build that is killed half way — a cancelled job, a closed terminal, a machine out of memory — leaves them rewritten, and the next build then "restores" the wrong thing. CI fails loudly when that happens; on your machine, look for changes in thirdparty/raymob/ and raymob/app/ after an interrupted build, and put the files back with git before building again.

What CI checks

Android is in the fast lane. On every push CI builds the debug APK and checks it holds a manifest and the native library; builds the release AAB, signs it and verifies the signature; checks from the compiler's own records that the release was compiled as a release; and checks that Gradle put back every source it rewrote. It does not run the game: an Android emulator on a CI runner is slow and fails for reasons that have nothing to do with the game. A release can also send the debug APK to Firebase Test Lab, to be started on a real phone — see Publishing.
