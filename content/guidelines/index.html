Guidelines

How C++ is written here: in the framework, in its examples, and in a game that wants to read like them. When a question has more than one good answer, three sources decide it, in this order, and a source lower down never overrules one above it.

Who decides

  1. The API is as simple as possible for whoever uses it. This outranks every other rule. A main menu is three functions, and a rule that would make it longer loses, whatever else it buys. The three-function menu says why.
  2. The framework's own decisions, each one with its reason: the naming table, one header per module, ownership, and no raw pointer in the API, no exceptions, designated initialisers in declaration order, and the rest of why it is built this way.
  3. Google's C++ Style Guide, for everything the first two leave open. Where the framework has decided otherwise, its decision holds, and the reason is written down with it.

Checked like the code

A rule on these pages is shown in code, and the code is checked the way the framework's own is. A block that shows the right way is compiled against the framework's headers and has to pass clang-tidy, with the framework's own .clang-tidy, without a single warning. A block that shows the wrong way and still compiles says what refuses it — a check of clang-tidy, which rmp lint runs, or a gate of rmp test — and the build of this site runs that check on it and fails if it stays quiet. A block that does not compile at all is shown as not compiling, with the words the compiler uses. Checked, not remembered lists the rules the framework's tools hold today.

What a game gets

A game made with rmp new gets .clang-format, so rmp fmt formats it the framework's way, and the one compiler flag the framework hands every target that links it: under Clang, designated initialisers out of declaration order are an error, as they already are under GCC and MSVC. It does not get the framework's .clang-tidy: rmp lint is a command of the framework's own repository, and a game chooses its own checks.

The pages

The rules themselves are being written, one page per subject: naming, formatting, const, pointers and ownership, strings, the parts of modern C++ the oldest compiler the framework supports can take, macros, where this framework and Google's guide part ways, and which tool holds which rule.
