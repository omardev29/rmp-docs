What checks what

A rule that only a document states lasts until the day somebody has not read the document. So each rule on these pages names the tool that refuses its mistake, and this page puts them in one table, with where each one holds: in the framework (its include/, src/ and tests/), in its examples, and in a game made with rmp new. The build of this site holds the table to the framework's own configuration, so a check that is said to run runs.

The tools

clang-tidy, which rmp lint runs
The checks of the framework's .clang-tidy over the sources of src/, tests/ and examples/, and the headers they reach, with the flags each file is built with. Whole families run — bugprone, clang-analyzer, performance, portability, misc, modernize, readability — minus what is switched off below, and the style guide's checks are named one by one. Two of them are queries the framework writes itself, which clang-tidy runs only with --experimental-custom-checks, and rmp lint passes it.
examples/.clang-tidy
The same file for the examples, narrowed: it switches off the modernize and readability families, which push a more elaborate spelling of correct code at someone learning raylib, and takes back the ones that are rules of these pages. An example teaches the C++ a game should write.
What the tree still owes
clang-tidy's warnings that the framework has not yet paid are listed in tools/lint_debt.txt, a count per check and file. rmp lint fails on a warning the list does not owe and on a count that grew, and the list only shrinks. A new warning is fixed, or carries a NOLINT with its reason on the line.
The text gates, stages of rmp test
What clang-tidy cannot see, because it parses one branch of every #if or because no check of its says it: tools/naming_check.sh (rules R1 to R8, the naming stage), tools/style_check.sh (S1 to S8, style), tools/ownership_check.sh (O1 and O2, ownership), tools/pointer_check.py, which reads the public headers' declarations (pointers), and tools/cppcheck_check.sh, a second analyser over src/rmp (cppcheck).
.clang-format, which rmp fmt applies
The layout of the code. The framework's CI fails on a file it would change; in a game, rmp fmt formats and rmp fmt check refuses a file it would change, when the game runs them: its rmp test and its CI do not.
The compiler
Every target CMake builds from the framework's sources and a game's is compiled with -Wall -Wextra under GCC and Clang: the desktop and the web, and not Android's or iOS's own projects. The framework's own checks build with RMP_WERROR, which makes a warning an error; a game's warnings stay warnings unless it asks for the same. Designated initialisers out of order are an error everywhere.

Written down, not checked

Some rules have no tool that can tell the right way from the wrong one. They are questions a reviewer asks:

  • const on a by-value parameter in a definition — clang-tidy does not look at parameters — and constexpr, consteval and constinit wherever they apply (const);
  • a std::array given a size larger than its list, whose rest is filled with zeros (Modern C++);
  • an unsigned type only for bits, and auto beyond a cast (Modern C++);
  • #pragma once at the top of a header, and <filesystem> in src/rmp/app.cpp and src/rmp/save.cpp only (Google's guide);
  • everything Google's guide says that no check of these pages states.

Switched off, and why

Each check the framework's .clang-tidy switches off fights a decision the framework has already made, and the file says which next to it. In the same words:

CheckWhy it is off
bugprone-easily-swappable-parametersEvery (float x, float y) in a 2D framework, which is all of them.
bugprone-narrowing-conversionsfloat and int mixing is what raylib's own API does; the static analyser catches the cases that lose data.
misc-non-private-member-variables-in-classesThe options structs and rmp::Object are public data by design (Google's guide).
misc-no-recursionThe layout walk is a tree walk.
misc-include-cleanerIt wants an #include for every raylib symbol, and raylib is one header.
misc-use-anonymous-namespace, misc-use-internal-linkagestatic at file scope is the deliberate spelling: main.cpp is the file a newcomer reads first, and it has a plain C twin among the examples, so the two keep the same shape. Google allows either.
modernize-use-trailing-return-typeauto f() -> int is not the style, nor Google's.
modernize-use-nodiscardIt would decorate the whole API for the few calls where it matters.
modernize-macro-to-enumThe values the .toml generates are macros on purpose: the C entry point reads them too (Macros).
modernize-use-designated-initializersIt suggests them inside the framework's implementation, where the field order is Clay's, not the framework's.
portability-avoid-pragma-once#pragma once is the framework's decision, and every compiler it builds with supports it (Google's guide).
performance-enum-sizePinning an underlying type on a public enum is churn in the ABI for bytes nobody is short of.
readability-redundant-member-initIn an options struct every field shows its default, even where the default is what the type would give anyway, and one field that does not is worse.

And for the examples, examples/.clang-tidy switches off misc-unused-parameters: a hook takes float delta whether this example's _update uses it or not, and the signature is the API's. It keeps readability-identifier-naming, readability-misleading-indentation and readability-misplaced-array-index from the family it switches off, and these six from modernize, each a rule of these pages: modernize-avoid-c-arrays, modernize-avoid-c-style-cast, modernize-use-nullptr, modernize-avoid-variadic-functions, modernize-use-std-numbers and modernize-use-using.

What the framework still owes

A rule that arrives after the code it judges finds the code breaking it. The framework writes that down instead of switching the rule off, and each list only shrinks: what clang-tidy still finds is tools/lint_debt.txt; the pointers left in its headers, each with its reason, are tools/pointer_ratchet.txt; the files allowed to own memory or raylib resources by hand, each with its reason, are in tools/ownership_check.sh; and what cppcheck may not say, each with its reason, is in tools/cppcheck_check.sh or on the line itself.

In a game

A game made with rmp new gets the formatter, rmp fmt, and the compiler's flags, which hold its designated initialisers to their order. None of the rest runs on its code: the rules are the advice the framework follows, and a game that wants to read like it can follow them too, and can switch the framework's clang-tidy on for its own code. What a game gets says the same from the game's side.
