Getting started

rmp is the one command: it makes a game, builds it, runs it, tests it and ships it. You install it once, and every game you make has its own copy.

What you need

  • Python 3.11 or newer, CMake 3.30 or newer and Ninja on your PATH, and a C++ compiler. A Linux distribution's own cmake package can be older than 3.30, and an older CMake stops the first build before anything is compiled: cmake --version says which one you have.
  • git, to get the framework and to keep your game in.
  • On Linux, the X11 development libraries:
sudo apt install libx11-dev libxrandr-dev libxi-dev libxcursor-dev libxinerama-dev libgl1-mesa-dev

Install rmp

Clone the framework into your home folder:

cd ~
git clone https://github.com/omardev29/raylib_multiplatform

Then put that folder on your PATH, once, in the file your shell reads when it starts:

ShellRun once
bash on Linuxecho 'export PATH="$HOME/raylib_multiplatform:$PATH"' >> ~/.bashrc
bash on macOSecho 'export PATH="$HOME/raylib_multiplatform:$PATH"' >> ~/.bash_profile
zshecho 'export PATH="$HOME/raylib_multiplatform:$PATH"' >> ~/.zshrc
kshecho 'export PATH="$HOME/raylib_multiplatform:$PATH"' >> ~/.profile
Windows: run it in PowerShell, and cmd sees it too[Environment]::SetEnvironmentVariable("Path", "$HOME\raylib_multiplatform;" + [Environment]::GetEnvironmentVariable("Path", "User"), "User")

On Windows, PowerShell also has to be allowed to run a script from your own disk, once: Set-ExecutionPolicy -Scope CurrentUser RemoteSigned. Open a new terminal so the PATH takes effect, and check:

rmp help

Make a game

rmp new my_game
cd my_game
rmp run

rmp new makes a folder with the framework, the build and CI for every target, and a small game in src/ to start from. rmp run builds it and opens the window: a menu with a rabbit on it. The first build compiles raylib and the framework, so it takes a while; after that only what changed is compiled again.

The folder is also a git repository, with every file already added. Commit it, so that what the next pages change is yours to see in git diff:

git commit -m "New game"

What is yours

Most of the folder is the framework and the build, and you do not edit it. Your game is six places:

PathWhat it is
src/main.cppWhere the game starts. It names the first scene, and that is all it does.
src/scenes/The scenes, one per file: main_menu.h and main_menu.cpp are the menu you just saw.
include/Your headers, when you want them apart from the code. This tutorial keeps each header beside its .cpp instead.
resources/Pictures and sounds, loaded by name. rabbit.png is the one on the menu.
branding/icon.pngThe app's icon: the Android and iOS icons, and the one inside the Windows .exe, are all made from this one picture. It is not in resources/ because the game never loads it.
raylib_multiplatform.tomlThe game's name, its window, its app ids and which platforms to build.

src/rmp/ and include/rmp/ are the framework itself, inside your game. Every other .cpp under src/, in any folder, is compiled without being listed anywhere: adding a file to the game touches no build file.

The new game's raylib_multiplatform.toml has your game's name in it, and app ids that start with com.example.. Set real ones before your first release: rmp deploy refuses to tag a release while they are placeholders, because a Google Play app id can never change once it is published.

The tutorial

The pages that follow turn the game rmp new made into a real one, a step at a time: Coin Rabbit, in which a rabbit gathers coins while bats close in on it. Each page shows every source file it adds or changes, whole, and the keys it sets in raylib_multiplatform.toml, and ends with a game that builds and runs.

  1. Your first scene: a menu of your own, and a second screen to go to.
  2. A player: an object that moves with the keyboard, a gamepad, the mouse or a finger.
  3. Coins and bats: something to collect, something to avoid, and a game over.
  4. A pause menu: a scene on top of the game.
  5. Art and sound: pictures and sounds, loaded by name.
  6. Saving a record: the best score, kept between sessions.
  7. Ship it: real app ids, the checks, and a release built for every platform.
