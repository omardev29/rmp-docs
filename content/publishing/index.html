Publishing

A release is a git tag. rmp deploy checks the version the way CI will, tags the commit and pushes the tag; CI then builds every target your game has turned on, boots the ones it can, and attaches all of them to a GitHub release. From there each build goes where its platform wants it: a zip to download, a folder on itch.io, a bundle for Google Play.

rmp deploy 1.2.0

There is no version number anywhere in the project. The tag is the version: v1.2.0 becomes the version Android and iOS show, the Android version code and the name of the release, so there is no number in a file to bump and none to forget. Releases and versions has the whole of it: the shape a tag must have, what rmp deploy checks and in which order, and how to take a tag back.

Before the first release

Four things are yours to decide once, and the first one cannot be changed afterwards.

  1. Give the game its real identifiers. rmp new writes com.example. ids for Android and iOS, and a release is refused while either one still starts with com.example.: Google Play keeps an application id for good, so a game published under a placeholder would keep the placeholder.

    [android]
application_id = "com.yourname.yourgame"

[ios]
bundle_id = "com.yourname.yourgame"

  2. Choose the targets. [targets] enabled starts as ["all"], which is {{count:targets}} of them. A target you switch off is not built, not tested and not released, and the release does not wait for it. The ids and the groups are in the configuration reference.

  3. Decide where the saves go. A zip that players unpack and run, which is what itch.io serves, wants [save] portable = true: the saves go in a folder beside the executable, and deleting the game deletes them. An installer, or Steam and its cloud saves, wants the default: the player's data folder. Desktop and BSD archives has the folders.

  4. Add the secrets you need, on GitHub. Nothing is needed for a release on GitHub itself. Signing for Google Play, uploading to itch.io and testing on Firebase each read secrets from the repository's settings, listed below. Without its secret each one says so in a warning and does without: the App Bundle is signed with a throwaway key, and nothing is uploaded or tested.

Then push your commits, so the commit you tag is one CI can check out:

rmp push
rmp deploy 1.0.0

What a release holds

One GitHub release per tag, with its notes generated by GitHub and, when the tag has a hyphen in it (v1.2.0-rc1), marked as a pre-release. Attached to it:

  • A zip per desktop and BSD target: the executable, its assets packed into one file, resources.rres, in a resources/ folder beside it, and LICENSES.txt. Desktop and BSD archives.
  • web-build.zip: the page, its script, the WebAssembly module and the preloaded assets. The web build.
  • The Android debug APK, and the signed App Bundle when the signing secrets are set. Google Play.
  • The iOS engine as an xcframework, and a simulator build of the app. The App Store.
  • THIRD_PARTY_LICENSES.md, and SHA256SUMS to check every download against.

The release is published only when every target that was built passed its checks. A tag that fails on any platform publishes nothing, so a release never has a hole where a platform should be.

Secrets and variables

Everything CI needs that is not a secret lives in raylib_multiplatform.toml, next to the rest of the game. Everything that is a secret lives in the repository's settings on GitHub, under Settings → Secrets and variables → Actions, and nowhere else. These are all of them — every name the workflows a game carries read:

NameKindFor
ANDROID_KEYSTORE_BASE64secretYour upload keystore, base64-encoded. With it set, CI signs the App Bundle with your key. Google Play
ANDROID_KEYSTORE_PASSWORDsecretThe keystore's password.
ANDROID_KEY_ALIASsecretThe key's alias inside the keystore.
ANDROID_KEY_PASSWORDsecretThe key's password.
ANDROID_SIGNER_CNvariableOptional. The CN of your upload key, so CI checks the bundle is signed by that key and not merely by some key.
BUTLER_API_KEYsecretAn itch.io API key, for butler. itch.io
ITCH_USER, ITCH_GAMEvariablesOptional. When set, they win over [deploy.itch] in the .toml.
GCP_SA_KEYsecretA Google Cloud service-account key, the whole JSON file, for Firebase Test Lab. Google Play
FIREBASE_PROJECT, FIREBASE_DEVICEvariablesOptional. When set, they win over [deploy.firebase] in the .toml.
FIREBASE_RESULTS_BUCKETvariableOptional. A Cloud Storage bucket the Test Lab results are written to and fetched back from.
IOS_SIMULATOR_TESTvariableOptional. true turns on the iOS simulator boot test, which is off. The App Store
Never

Never put a secret in raylib_multiplatform.toml. The file is committed, so anything in it is readable by everyone who can read the repository, for as long as the history exists. The keys the .toml does have under [deploy] — an itch.io user name, a Google Cloud project id — are names, not credentials.
