Every dependency

Everything the framework needs that it did not write, grouped by how it reaches a build, with the way each one is pinned and the check that holds the pin. The last section is a map of every file that names each dependency, made from the framework's tracked files when this site is built: the answer to "if I change this, what else do I look at?".

The kinds of pin

Pinned byMeansUsed for
Being committedThe files in the repository are the version. Nothing to fetch, nothing that can disappear.raylib, raylib-cpp, Clay, cute_tiled, raymob, doctest, and the rest of thirdparty/
Its content's sha256A committed copy that must not change without its licence row saying it is modified: tools/license_db.py recomputes the hash.cute_aseprite, cJSON, rres, doctest, RapidCheck (the sha256_* keys)
A version and a checksumA file fetched by address and refused unless its bytes hash to the pinned value.everything the image downloads; zig and UPX outside it, Ninja, XcodeGen, Mesa, Pillow
A digestAn image named by its content. A tag can be moved; a digest cannot.the build image, the Alpine run image, the image's Ubuntu base
A commitA full commit hash, never a tag.every GitHub Action, the raylib-iOS submodule, emsdk inside the image, the framework commit the image warms Gradle from
A snapshotEvery apt source of the image points at snapshot.ubuntu.com at one timestamp.every package the image installs with apt
A lockEvery package of the graph with == and the hash of every file.the image's Python test tools; Playwright's package-lock.json
A labelA name the provider resolves; it changes under you when the provider updates it.the runner images (ubuntu-24.04, windows_runner, macos_runner) and the BSDs' package mirrors

The last row is the weak one, and the only one that moves without a commit. Every other pin changes only when someone changes it.

There is no reason to upgrade any of these on a schedule. Each one is upgraded when a game needs something the new version has, or when a bug is found that upstream has fixed — and many of those fixes are carried as backports already. Upgrading raylib and the entries after it say how.

Python and Node

Python, 3.11 or newer
Every build needs it: CMake runs the generator on every configure. The generator, rmp and most tools use the standard library only. What is not standard library is optional on a laptop: Pillow for the icons, PyYAML for one workflow check, Hypothesis for the Python properties. Python has all of it.
Node, for the web test only
package.json names Playwright and pngjs, locked by package-lock.json and installed with npm ci; the browser Playwright downloads is keyed to its version. Dependabot proposes their bumps monthly. Nothing a game ships uses Node.

Every pin, as the framework holds it

The versions block of thirdparty/FROZEN_VERSIONS.md, read when this site is built. A long digest is cut to its first sixteen characters.

What names each dependency

For each dependency, how many files of each kind name it, and then every one of those files with how often. It is a regular expression over the framework's tracked files (the vendored copy itself left out, its PATCHES.md and the pins kept) and over this site's pages, run when the site is built, so it is true of the commit this site documents. A count is where to look, not a verdict: a file that names Gradle once in a comment is in it beside the file that builds with it.

The regular expressions are DEPENDENCIES in generated.py, the module of this site's build that makes the table; a test there fails on one that matches nothing in the framework. A new dependency gets its line in the same pull request that adds it.
