Why it is built this way

A framework is mostly decisions, and a decision you cannot see the reason for looks like an accident. These pages give the reasons: why a menu is three calls, why a hook starts with an underscore, why nothing throws, why every struct of options is ordered the way it is. Each one is a rule the framework holds itself to, and most of them are checked by a tool rather than remembered.

The rule above the others

The three-function menu. The API has to be as simple as possible for the person making the game, and a main menu written in three calls is the measure. Every other decision on these pages is answerable to it.

How the code reads

Naming
One spelling per kind of name, so a type, a value and a constant never look alike where they are used, and no prefix carries meaning a dot can carry better.
The access rule
_name is a method of yours the framework calls; on_name is a function you hand to it. Two spellings, two directions.
Designated initialisers
Why options are written { .speed = 320 }, why the order of the fields matters, and why a behavior has no base class.
Macros
Where a macro is the right tool — the entry point, the values from the .toml — and the one rule about them: a header never makes you use one.

How the framework holds together

One header per module
No umbrella header, headers that do not include each other, and the cost of every include measured rather than guessed.
Ownership
Everything is owned by something that releases it: a texture, an object, a scene, a callback. No raw pointer in the API, nothing you have to free, and the handle for what you keep across frames.
No exceptions
What the framework does instead of throwing, and why throwing in the middle of a frame is not an option.
Time is a parameter
Why every hook is handed delta, where the clock is read, and what [app] max_delta protects you from.

Checked, not remembered

A rule written only in a document is kept until the day someone has not read it. So wherever a mistake can be described precisely, something in the framework's own test run rejects it:

RuleWhat enforces it
Naming, and the eight hook names.clang-tidy, -Wshadow and tools/naming_check.sh
The style guide: const on what does not change, std::array, enum class, static_cast, no raw pointer, a constant in a header inline constexpr, a macro only for what a function cannot do.clang-tidy, two of whose checks are queries of the framework's own and run only with --experimental-custom-checks; what the tree still owes it is written down in tools/lint_debt.txt, which only shrinks
The style rules clang-tidy cannot see, in every branch of every #if: no C cast, no NULL, no TODO, nothing newer than the oldest compiler a game is built with, no user-defined literal, ++i where the old value is not readtools/style_check.sh
No finding of a second analyser in src/rmp, and a reason beside every suppressiontools/cppcheck_check.sh
No owning raw pointer in the framework, and no raylib Load* or Unload* outside the file that owns what it makestools/ownership_check.sh, and two ownership checks of clang-tidy
No raw pointer and no C string in a declaration a game can nametools/pointer_check.py, against tools/pointer_ratchet.txt
Every public header compiles on its own and carries the .toml valuestools/header_check.sh
What each public header costs to includetools/header_cost.py, against tools/header_budget.txt
Nothing in the framework reads the clock, the input or the random state on its owntools/seam_check.sh
A mistake in the .toml stops before the buildtools/configure.py, and tests/configure_test.py for each refusal
Every vendored component has a licence the project can shiptools/license_db.py
No memory error and no undefined behaviour in a test runevery debug build of the framework under AddressSanitizer and UndefinedBehaviorSanitizer, from cmake/sanitize.cmake, and tools/sanitize_check.sh for a second compiler
Every release binary stays the size it was measured at, unless the growth is written downtools/size_check.py, against tools/size_budget.txt
No file of the framework falls below the share of its lines its tests are written down to run, and no public function arrives without a test that calls ittools/coverage_report.py, against tools/coverage_floor.txt and tools/untested_api.txt

The scripts are stages of the framework's rmp test, clang-tidy is rmp lint, which fails on a warning tools/lint_debt.txt does not owe, and the CI runs all of them on every push. Testing has the rest.
