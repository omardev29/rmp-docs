One header per module

There is no header that includes the whole framework. There are {{count:headers}} headers under include/rmp/, one for each part of the framework you can name — the UI, the input, the assets, the audio — and a file includes the ones it uses. That is what makes each module optional: you take the whole ecosystem, or you take one piece of it.

A file that draws the HUD looks like this:

#include <rmp/ui.h>

#include <string>

void draw_hud(int score, float health) {
    rmp::ui::begin({ .placement = rmp::ui::Align::TOP_CENTER });
    rmp::ui::row({ .gap = 24 }, [&] {
        rmp::ui::text(std::to_string(score));
        rmp::ui::progress(health);
    });
    rmp::ui::end();
}

It knows about the interface and nothing else, so it recompiles when the UI changes and not when the asset pipeline does. And when it reaches for something it did not include, the compiler says so, by name:

#include <rmp/ui.h>

void draw_pause_hint() {
    rmp::ui::begin();
    if (rmp::input::just_pressed("pause")) rmp::ui::text("Paused");
    rmp::ui::end();
}

That error is the truth: the file is missing rmp/input.h. An umbrella header would have hidden it, and every file would have paid to compile all of the framework to use one part of it. An example holds the framework to this: it includes only rmp/ui.h, and the examples build fails if that stops being enough.

A header is a module you can name

Splitting is not free for the person using the framework: every header is one more thing they have to know exists. So a new header has to be a part of the framework you can name and decide to use or not — rmp::ui, rmp::audio, rmp::save. Anything else goes into a header that already exists. Splitting for tidiness only taxes the reader, and the number of includes a game needs is a number that should go down over time, never up.

Our headers do not include each other

A header under include/rmp/ declares what it needs from another one instead of including it, wherever the language allows. Where it does not — a type held by value has to be complete — the header includes the other one and says at its top why it could not avoid it. Those are the exceptions, and they are few:

HeaderIncludesBecause
rmp/scene.hrmp/object.h, rmp/tilemap.ha scene spawns objects, and holds its map by value
rmp/object.hrmp/assets.ha sprite holds its texture by value
rmp/tilemap.hrmp/object.ha map's object factories are callbacks
rmp/behavior.hrmp/object.h, rmp/scene.hthe catalogue holds handles and callbacks by value, and a spawner hands you the scene

If a pair of headers ever needed each other, one of them should not exist: they would be one module pretending to be two.

The technique that makes most of this possible is moving the call into a .cpp. The entry-point macros in rmp/app.h have to start the asset layer and close the UI, but naming rmp::assets or rmp::ui there would make every file with an entry point compile both. So the macros call a handful of functions declared in rmp/app.h and defined in src/rmp/app.cpp, which is the one file that includes the rest.

The one header every header includes

Every public header includes rmp/config.h, the values from the .toml, so RMP_WINDOW_WIDTH and the rest are simply there wherever you are writing and you never type that include. It is the exception to the rule above, and it earns it by measurement: it is nothing but #defines with no includes of its own, and parsing it costs no more than parsing an empty file. tools/header_check.sh compiles every public header on its own and uses RMP_WINDOW_WIDTH after it, so a header that forgets it — or that only compiles when something else was included first — fails the framework's tests rather than a game's build.

The standard library is allowed; its cost is measured

The rule is about the framework's own headers. It was never a rule against the standard library or raylib: <memory>, <vector>, <string_view> and raylib.h are used where the job needs them. What the framework does instead is measure what each include costs, and keep the number from creeping up unnoticed.

tools/header_cost.py preprocesses a file that includes one public header and nothing else, and counts the lines of code that come out. That count is the same on every run with the same compiler, so it is what the gate compares, against tools/header_budget.txt, inside the pinned build image the budget was measured in: a header that grows by more than a fifth fails, and so does one that shrinks by as much, because a budget left too high would let the next growth through. A header with no line in the budget fails everywhere. Milliseconds are reported too, because they are what a person feels, but they are never gated: they depend on the machine.

The measurements are written down where the decisions are made, and some of them decided the API:

  • rmp::Callback exists because <functional> measured 131 ms in every file that includes rmp/object.h, which is every file with an object in it, and the part of std::function the framework needs is small. It turned out to have a second reason, in Ownership.
  • Sprite::play() takes a const char * and not a std::string_view, which measured 77 ms in the same files, because animation tags are string literals in practice.
  • rmp/math.h is a header of its own because the C library's <math.h> under raymath is most of its cost, and rmp/ui.h must not make a file that only draws menus pay for it.
